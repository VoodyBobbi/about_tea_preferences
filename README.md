# incoming_lids — чайный консультант

Telegram-бот-консультант по подбору чая. Вежливо выясняет предпочтения клиента через
анкету из 11 факторов, ищет подходящий чай в интернет-магазинах, предлагает клиенту
несколько вариантов на выбор и передаёт оформленную заявку в чат менеджеров.

Бот:

- общается с клиентом в чате и отвечает на произвольные вопросы о чае как эксперт;
- проводит анкету предпочтений через inline-кнопки (со свободным текстом как fallback);
- ищет чай в интернете (Tavily) по площадкам, где идёт продажа;
- показывает клиенту 5-6 подходящих вариантов кнопками — без цены и без источника;
- после подтверждённого выбора отправляет заявку в Telegram-чат менеджеров.

## Что собирает бот

Профиль клиента: имя, контакт, адрес доставки.

Анкета из 11 факторов: цель приёма чая, основной вкус, уровень кофеина, ферментация,
крепость вкуса в чашке, аромат, размер частиц листа, способ заваривания, ограничения
здоровья/аллергии, особые пожелания, предыдущий опыт с чаем. Полный каталог вопросов и
вариантов — в `core/tea_factors.py`.

Заявка считается готовой не после анкеты, а только когда клиент подтвердил выбор
конкретного чая среди предложенных вариантов — именно в этот момент она уходит оператору.

## Как работает

1. Клиент пишет `/start` — бот спрашивает имя, затем адрес доставки (контакт
   подставляется из Telegram-username автоматически, если он есть).
2. Дальше бот проводит анкету из 11 факторов: на каждый вопрос показывает inline-кнопки
   с вариантами; можно нажать «Другое» (где это предусмотрено) или просто написать текстом
   — свободный ответ тоже распознаётся через LLM. Вопрос о чае в любой момент анкеты не
   сбивает прогресс — бот отвечает и возвращается к текущему вопросу.
3. Когда все 14 полей (профиль + анкета) собраны, `TeaWorkflowService` строит поисковый
   запрос (с приоритетом на факторы высокой важности) и обращается к Tavily.
4. `TeaAssistant` превращает сырые результаты поиска в 5-6 персонализированных
   рекомендаций (отдельный LLM-вызов со строгой JSON-схемой) — с названием и коротким
   описанием, без цены; источник (ссылка) в этом сообщении клиенту не передаётся.
5. Клиент видит варианты кнопками и либо выбирает чай, либо нажимает «Найти ещё» — тогда
   бот ищет заново, исключая уже показанное; если принципиально новых вариантов нет,
   честно предлагает ближайшие как компромисс.
6. После выбора заявка — источник, название чая, адрес доставки, имя клиента, контакт в
   Telegram — уходит в чат менеджеров. Дальше менеджер сам созванивается с клиентом.

## Переменные окружения

```env
TELEGRAM_BOT_TOKEN=your_telegram_bot_token
OPERATOR_CHAT_ID=-1001234567890

OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=https://api.openai.com/v1

TAVILY_API_KEY=your_tavily_api_key
TAVILY_BASE_URL=https://api.tavily.com
TAVILY_MAX_RESULTS=8

LOG_LEVEL=INFO
```

`TAVILY_API_KEY` — ключ с [tavily.com](https://www.tavily.com/); есть бесплатный тариф,
достаточный для тестирования сценария.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # затем заполнить .env
python main.py
```

Через Docker — как и раньше:

```bash
docker build -t tea-bot .
docker run --name bot --env-file .env -d tea-bot
```

## Важно

- Сессии хранятся в памяти процесса. После перезапуска бота вся анкета сбрасывается.
- Если у пользователя есть `@username`, бот использует его как Telegram-контакт по умолчанию.
- Если технически падает LLM-вызов при сборе одного поля — бот просто просит повторить
  ответ (без попытки угадать поле регулярками, как было в исходном support-боте: под 14
  разноплановых полей с кнопками такой fallback не масштабируется и не даёт ощутимой пользы).
- Если падает поиск в Tavily — сессия остаётся в состоянии «анкета заполнена», и следующее
  любое сообщение клиента повторяет попытку поиска с этого же места, не переспрашивая анкету.
- Для прода стоит добавить постоянное хранилище сессий, более тонкий retry/backoff и аудит
  сообщений — как и в исходном проекте.
